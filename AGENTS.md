# Правила работы с проектом

## Процесс

- Коммиты и отправку изменений выполняй только по явному запросу пользователя.
- Изменяй README.md только по явному запросу пользователя.

## Окружение и зависимости

- Используй Python 3.13, Poetry и выбранное разработчиком окружение pyenv.
- Используй только PostgreSQL для приложения и тестов; не добавляй SQLite
  или автоматическое переключение на другую базу.
- Не создавай `.venv` и не включай создание окружений Poetry.
- Не изменяй локальный выбор окружения в `.python-version`.
- Запускай Python-инструменты через `poetry run python -m ...`, команды Django —
  через `poetry run python manage.py ...`.
- Добавляй зависимости через Poetry и обновляй `poetry.lock` вместе с
  `pyproject.toml`. Инструменты разработки помещай в группу `dev`.
- Не сохраняй в репозитории секреты и абсолютные пути с компьютеров участников.

## Код

- Соблюдай настройки Ruff, mypy и Pyright из `pyproject.toml`.
- Добавляй комментарии только для неочевидных бизнес-правил, ограничений библиотек
  и сложных участков. Не комментируй очевидные действия кода.
- Сохраняй комментарии и docstring, сгенерированные Django или другими
  инструментами. Не удаляй их ради предыдущего правила.
- Не исключай файлы из анализа типов только потому, что они сгенерированы.
  Не отключай проверки целиком ради отдельной ошибки.
- Для работы с данными и API используй возможности Django и DRF; избегай
  дублирования стандартного поведения без необходимости.
- Изменения моделей сопровождай миграциями. Проверяй права доступа тестами
  для разрешённых и запрещённых действий.

## Проверки

- `make check` — Ruff, проверка форматирования, mypy, Pyright, OpenAPI и pytest.
- `make lint` — Ruff и проверка форматирования без изменения файлов.
- `make format` — исправления Ruff и форматирование с изменением файлов.
- `make typecheck` — mypy и Pyright.
- `make test` — pytest.
- `make schema` — генерация и валидация OpenAPI без предупреждений.
- После изменения кода запускай `make check`. После изменения моделей также
  запускай `poetry run python manage.py makemigrations --check --dry-run`.
- Если проверка не выполнена или завершилась ошибкой, явно сообщи об этом.

## Структура

- `config/` — настройки Django, маршруты, ASGI и WSGI.
- `api/` — маршруты API, сериализаторы и представления.
- `tasks/` — модели задач и комментариев, регистрация в админке и миграции.
- `docs/domain.md` — схема данных и планируемые правила доступа API.
- `tests/` — автоматические тесты; тестовая база управляется pytest-django.
- `.github/workflows/` — проверки и сборка контейнера.
- `Makefile` — общие команды разработки и проверок.
- `AGENTS.md` — общие инструкции Codex, версионируемые вместе с проектом.

## Расширение настроек Codex

- Постоянные правила проекта поддерживай в этом файле.
- Повторяемые специализированные процедуры оформляй при необходимости
  в `.agents/skills/<имя>/SKILL.md`.
- Общие настройки Codex при необходимости добавляй в `.codex/config.toml`.
  Проектный конфиг загружается только для доверенных проектов.
- Личные настройки, авторизацию и локальное состояние Codex не переноси
  из домашнего каталога разработчика в репозиторий.
