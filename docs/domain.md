# Модель данных и правила доступа

## Данные

Используется стандартная модель пользователя Django. Связи моделей задаются
через `AUTH_USER_MODEL`.

| Поле Task | Значение |
| --- | --- |
| id | Числовой первичный ключ |
| title | Обязательное название, до 255 символов |
| description | Описание, по умолчанию пустая строка |
| author | Обязательный автор |
| assignee | Один исполнитель или NULL; допустимо назначить задачу себе |
| is_completed | Признак завершения, по умолчанию false |
| created_at | Время создания |
| updated_at | Время последнего сохранения задачи |

| Поле Comment | Значение |
| --- | --- |
| id | Числовой первичный ключ |
| task | Обязательная задача |
| author | Обязательный автор комментария |
| text | Обязательный текст, до 10 000 символов |
| created_at | Время создания |

Задачи сортируются от новых к старым, комментарии — от старых к новым.
Первичный ключ используется для однозначного порядка при одинаковом времени.

Имена `author_id`, `assignee_id` и `task_id` в API соответствуют внешним ключам
моделей. Автор берётся из текущего пользователя, задача комментария — из URL.

## Целостность и удаление

- Удаление задачи каскадно удаляет её комментарии.
- Удаление пользователя, назначенного исполнителем, снимает назначение.
- Пользователя с авторскими задачами или комментариями удалить нельзя,
  пока существуют эти записи. Для отключения доступа можно использовать
  стандартный флаг `is_active`.
- В базе запрещены пустые строки в названии задачи и тексте комментария.
- Ограничения длины и обязательность полей проверяются валидацией Django;
  в API будет применяться валидация сериализаторов DRF.

## Политика API

Все операции с задачами и сессионная авторизация реализованы.
Комментарии и список пользователей пока остаются
заглушками. Таблица ниже задаёт политику всего API; для ещё не реализованных
действий она описывает целевое поведение. Модели сами по себе не обеспечивают
права доступа API.

`POST /api/v1/tasks/` создаёт задачу и возвращает её данные с кодом `201`.
Обязательно только поле `title`; `description`, `assignee_id` и `is_completed`
необязательны. Исполнитель должен существовать и быть активным; `null` означает
отсутствие исполнителя. Допустимо создать уже выполненную задачу.

Автор берётся из сессии. Переданные клиентом `id`, `author_id`, `created_at`
и `updated_at` игнорируются как поля только для чтения. Ошибки валидации
возвращают `400` без создания записи; отсутствие авторизации или корректного
CSRF-токена возвращает `403`.

`GET /api/v1/tasks/` возвращает только задачи текущего пользователя как автора
или исполнителя. Ответ содержит `count`, `next`, `previous` и `results`.
Размер страницы — 20, номер задаётся параметром `page`. Количество записей
и ссылки страниц вычисляются после ограничения доступа. Неверная или
несуществующая страница возвращает `404`.

`GET /api/v1/tasks/{id}/` возвращает доступную задачу. Для чужой или
несуществующей задачи возвращается одинаковый ответ `404`. После переназначения
бывший исполнитель теряет доступ сразу. Список и просмотр не требуют CSRF-токена.

`PUT /api/v1/tasks/{id}/` доступен только автору и требует `title`.
`PATCH /api/v1/tasks/{id}/` позволяет автору менять отдельные поля. Неуказанные
необязательные поля при PUT и PATCH сохраняют свои прежние значения.
Поля автора, ID и дат остаются только для чтения.

Текущий исполнитель может отправить PATCH только с полем `is_completed`,
чтобы завершить или повторно открыть задачу. Если переданы другие поля,
включая поля только для чтения, весь запрос отклоняется с `403` без изменений.
При совмещении ролей автора и исполнителя действуют права автора.

Назначение выполняется автором через `assignee_id`; `null` снимает назначение.
Нельзя назначить несуществующего или неактивного пользователя. Успешное изменение
возвращает `200` с данными задачи. Ошибка валидации возвращает `400`, чужая задача —
`404`. Изменение обновляет `updated_at`, сохраняя автора и время создания.

`DELETE /api/v1/tasks/{id}/` доступен только автору. Успех возвращает `204`
без тела ответа и удаляет задачу вместе с её комментариями. Пользователи и
остальные задачи сохраняются. Исполнитель получает `403`, остальные пользователи —
`404`. Для несуществующей или уже удалённой задачи возвращается `404`.
Удаление через сессию требует корректный CSRF-токен.

| Действие | Автор задачи | Текущий исполнитель | Остальные пользователи |
| --- | --- | --- | --- |
| Просмотр задачи и комментариев | Да | Да | Нет |
| Изменение названия и описания | Да | Нет | Нет |
| Назначение или снятие исполнителя | Да | Нет | Нет |
| Завершение и повторное открытие задачи | Да | Да | Нет |
| Удаление задачи | Да | Нет | Нет |
| Добавление комментария | Да | Да | Нет |

Любой активный авторизованный пользователь может создать задачу и назначить
её активному пользователю. Список пользователей для назначения содержит только
активные аккаунты и не раскрывает email и другие личные поля.

Если пользователь одновременно автор и исполнитель, применяются права автора.
После переназначения прежний исполнитель теряет доступ; его комментарии
сохраняются. Признак `is_staff` не даёт дополнительных прав в API: административный
доступ обеспечивается отдельно через Django Admin и её разрешения.

Списки задач фильтруются по автору и исполнителю. Для чужой задачи ручки
просмотра, изменения, удаления и комментариев возвращают 404. Запрещённое действие
над доступной задачей возвращает 403. Без входа закрытые ручки возвращают 403.
Изменяющие запросы через сессию требуют корректный CSRF-токен.
